# 脚本管理优化 — 头脑风暴记录

## 背景

当前脚本管理使用纯 textarea 编辑 JavaScript 脚本，没有任何语法辅助。脚本遵循 Clash Verge 规范，定义 `main(config, profileName)` 函数，操作 `proxies`、`proxy-groups`、`rules` 数组。

## 问题空间

- 脚本编辑体验差：纯文本，无高亮、无错误提示
- 无法在保存前验证脚本是否正确
- 不知道脚本执行后会产生什么效果

## 方案对比

### 编辑器选择

| 选项 | Monaco | CodeMirror 6 | Ace |
|------|--------|-------------|-----|
| 体积 (gzip) | ~800KB | ~150KB | ~250KB |
| 功能完整度 | 最强（VS Code 内核） | 良好 | 良好 |
| JS 错误诊断 | 内置支持 | 需插件 | 需插件 |
| Vue 集成 | 需封装 | 社区组件 | 社区组件 |

**决策**：选 Monaco。用户明确表示看重功能完整度，体积不敏感。

### 调试能力

讨论了三个级别：
1. Level 1 — 纯前端语法高亮 + 错误提示
2. Level 2 — 后端试运行 + 结果展示
3. Level 3 — 断点调试（需 DAP 协议桥接 GraalVM Inspector）

**决策**：Level 1 + Level 2。Level 3 工程量过大，暂不做。

### 试运行数据来源

讨论了三种来源：pipeline 最近构建结果 / 手动选订阅源 / 模拟 config。

**决策**：用户手动选择订阅源，后端实时获取该订阅源的配置。

### AST 注入 vs GraalVM Inspector

讨论了两种调试方案：
- 方案 A：GraalVM Inspector + DAP Bridge（真正断点，但复杂度高）
- 方案 B+：AST 注入追踪 + 手动断点（轻量但只是模拟）

**决策**：放弃断点功能，只做高亮 + 试运行。

## 最终范围

- ✅ Monaco Editor 替代 textarea（语法高亮、括号匹配、JS 错误诊断）
- ✅ 试运行功能（选择订阅源 → 执行脚本 → 返回变更摘要或错误）
- ✅ 格式化按钮
- ✗ 断点调试
- ✗ 脚本模板插入
- ✗ 智能补全
