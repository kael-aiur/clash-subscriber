## Context

订阅源详情页面的代理节点标签页当前以 `el-table` 平铺展示所有节点（名称、类型、服务器、端口）。当节点数量多时（数十到上百个），逐条浏览非常混乱。

规则标签页已实现双层分组（策略 → 规则类型），使用 `el-collapse` + `el-collapse-item` 支持展开/折叠，体验良好。用户希望代理节点采用类似的交互模式。

大部分节点名称包含国旗 emoji（如 `🇭🇰 香港 | 00`），为按地区分组提供了可靠的数据基础。

**约束**：仅修改前端 `SubscriptionView.vue`，不涉及后端 API 变更。

## Goals / Non-Goals

**Goals:**
- 代理节点按地区（国旗 emoji）分组展示，每组支持点击展开/折叠
- 维护国旗 emoji → 中文地区名映射表，覆盖常见地区
- 无地区标识的节点归入"其他"分组
- 支持按节点名称搜索过滤，空组自动隐藏
- 交互模式与规则标签页保持一致

**Non-Goals:**
- 不修改后端 API 或数据模型
- 不实现双层分组（地区 → 类型）
- 不新增组件文件或 npm 依赖
- 不处理节点去重或排序优化

## Decisions

### D1：单层分组（仅地区）

- **选择**：只按地区分组，不嵌套第二层（节点类型）
- **理由**：用户需求明确为"按地区分组"，双层增加复杂度但无明显收益
- **已考虑 alternative**：双层分组（地区 → 类型）—— 增加 UI 复杂度，用户未提出此需求

### D2：国旗 emoji 解析 + 预设映射表

- **选择**：从节点名称开头匹配国旗 emoji，通过映射表转换为中文地区名
- **理由**：国旗 emoji 是最可靠的地区标识，映射表确保所有常见国旗都能正确显示中文名
- **已考虑 alternative**：
  - 纯 emoji 匹配无映射表 —— emoji 本身无法显示中文地区名
  - 文本关键词匹配 —— 命名风格不统一，可靠性低
  - 后端提取 region 字段 —— 对纯展示需求过度设计，改动范围大

### D3：无标识节点归入"其他"

- **选择**：没有国旗 emoji 的节点统一归入"其他"分组
- **理由**：不丢失任何节点，用户仍可在"其他"中找到未标识地区的节点
- **已考虑 alternative**：
  - 单独平铺展示 —— 破坏统一的分组交互模式
  - 隐藏这些节点 —— 可能丢失有效信息

### D4：组内保持表格展示

- **选择**：每个地区分组展开后，内部仍用 `el-table` 展示节点详情
- **理由**：与当前体验一致，用户已熟悉表格列的含义
- **已考虑 alternative**：
  - 标签/徽章展示 —— 节省空间但缺少详情信息
  - 卡片网格 —— 视觉丰富但占空间

### D5：纯前端实现

- **选择**：所有逻辑在 `SubscriptionView.vue` 中实现，不修改后端
- **理由**：地区分组本质是展示层优化，前端处理最简洁，改动最小
- **已考虑 alternative**：后端在 `ProxyNode` 模型中增加 `region` 字段 —— 改动范围大，对纯展示需求过度设计

## Risks / Trade-offs

- [Risk] 国旗 emoji Unicode 匹配在不同浏览器/系统上可能有差异 → Mitigation：使用 `\p{Emoji_Presentation}` Unicode 属性类匹配，兼容现代浏览器；映射表覆盖常见国旗
- [Risk] 部分服务商节点命名不含国旗 emoji，全部归入"其他"可能导致该组过大 → Mitigation：接受此限制，"其他"组仍可展开浏览
- [Trade-off] 前端硬编码映射表，新增国旗需改代码 → 接受理由：常见地区稳定，新增频率极低
