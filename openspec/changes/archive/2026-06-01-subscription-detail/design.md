## Context

当前订阅源管理页面（SubscriptionView.vue）仅展示列表信息（名称、URL、最后获取时间），点击"获取"后弹出简单统计弹窗。用户需要查看订阅源的详细内容（节点、节点组、规则）时，只能手动导出 YAML 文件查看。

现有后端接口 `POST /api/subscriptions/{id}/fetch` 已返回完整的 ClashConfig 数据（proxies、proxyGroups、rules），前端 TypeScript 类型定义也已包含这些字段。因此本次变更仅需新增前端 UI 组件，无需后端改动。

## Goals / Non-Goals

**Goals:**
- 从订阅源列表点击"详情"即可查看完整配置内容
- 四个标签页覆盖 ClashConfig 的全部核心数据：基本信息、代理节点、节点组、规则
- 节点组展示组内成员关系，帮助用户理解订阅的路由结构
- 规则支持搜索/筛选，应对上千条规则的场景

**Non-Goals:**
- 不支持在线编辑订阅配置
- 不支持节点测速或延迟测试
- 不支持规则的增删改操作
- 不修改现有后端 API

## Decisions

### D1：使用抽屉（Drawer）而非新页面

- **选择**：点击"详情"按钮打开右侧 el-drawer 抽屉
- **理由**：保持在订阅源列表的上下文中，用户查看详情后可快速关闭回到列表，无需页面跳转
- **已考虑 alternative**：
  - 独立详情页面 — 拒绝，需要路由配置，且离开列表后返回需重新加载
  - 弹窗（Dialog） — 拒绝，弹窗面积有限，不适合展示大量表格数据

### D2：节点组使用可展开表格

- **选择**：el-table 配合 expand 行，展开后以 tag 列表展示组内节点名称
- **理由**：与代理节点、规则标签页的表格风格保持一致；展开行能直观展示组与节点的包含关系
- **已考虑 alternative**：
  - 卡片 + 抽屉 — 拒绝，信息密度低，且与其他标签页风格不统一
  - 树形组件 — 拒绝，el-tree 与表格混用视觉不协调

### D3：复用 fetch 接口数据

- **选择**：点击"详情"时调用 `POST /api/subscriptions/{id}/fetch`，将返回的 ClashConfig 存入组件状态供四个标签页使用
- **理由**：fetch 接口已返回完整数据（含缓存降级），无需新增后端接口
- **已考虑 alternative**：
  - 新增专用详情 API — 拒绝，fetch 接口已满足需求，增加接口徒增复杂度

### D4：规则表格支持搜索

- **选择**：在规则标签页顶部添加搜索输入框，实时过滤规则列表
- **理由**：订阅规则数量可达上千条，无搜索则几乎无法使用
- **已考虑 alternative**：
  - 分页展示 — 拒绝，规则查找通常是关键词搜索而非顺序浏览

### D5：前端类型补全

- **选择**：在 `api/subscription.ts` 中补充 ProxyNode 和 ProxyGroup 的 TypeScript 接口定义
- **理由**：当前 `proxies` 类型为 `unknown[]`，`proxyGroups` 为 `Record<string, unknown>`，无法在模板中安全访问字段
- **已考虑 alternative**：
  - 使用 `any` 类型 — 拒绝，丧失类型安全，模板中无代码提示

## Risks / Trade-offs

- [风险] 节点组 proxies 列表包含非节点名称的文本（如服务商广告信息）→ 在 tag 展示时不做特殊处理，保持原始数据
- [风险] 大量节点（100+）展开行时渲染性能 → 仅在展开时渲染，非虚拟列表，当前数据量可接受
- [取舍] 点击详情会触发一次网络请求（fetch） → 接受，fetch 接口有缓存降级机制，网络不可用时返回缓存数据
