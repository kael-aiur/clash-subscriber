# 构建历史详情 — 配置内容展示

## 背景

当前构建历史详情页面中，各步骤的输入输出只显示简单的 ID 和描述文本：
- 拉取主订阅配置：input = 订阅 ID，output = "节点数: 25"
- 合并额外订阅节点：input = 额外订阅 ID 列表，output = "合并后节点总数: 50"
- 脚本处理：input = 脚本名称，output = "脚本处理完成"
- 推送到 Mihomo：input = 实例 ID，output = "配置推送成功"

用户希望看到更丰富的内容：订阅源名称、实际配置内容（YAML）、以及用卡片展示的配置摘要。

## 决策记录

### Q1: 配置数据来源
**决策**: 构建时保存完整快照到 BuildStep 的 input/output 字段中。
**原因**: 历史记录不会因订阅源修改而变化，数据一致性好。

### Q2: 卡片信息层次
**决策**: 数字摘要（节点数、代理组数、规则数）+ 预览信息（前 N 个节点名称、代理组名称）。
**原因**: 预览信息帮助用户快速识别配置内容，无需展开即可判断。

### Q3: 展开范围
**决策**: 所有步骤的配置卡片都可展开查看完整 YAML。
**原因**: 统一交互模式，用户可在任意步骤查看完整配置。

### Q4: 数据存储方案
**决策**: 复用 BuildStep 的 input/output 字段存储结构化对象（方案 A）。
**原因**: 不需要修改 BuildStep 模型，兼容现有数据，实现简单。

## 设计取舍

### 存储大小 vs 可追溯性
选择在构建记录中保存完整 YAML 快照。代价是存储空间增大，但收益是历史记录完全独立、可追溯。

### 结构化对象 vs 新增字段
选择复用 input/output 字段。代价是类型不够显式，但收益是模型无需变更、向后兼容。

### ConfigCard 组件
新建独立的 ConfigCard.vue 组件，负责展示配置摘要和可展开的 YAML 内容。所有步骤复用同一组件。
