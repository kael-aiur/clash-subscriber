# Clash 配置生成器 - Brainstorm

## 背景

用户需要一个独立的 "Clash 配置生成器"，支持 Clash Verge 等客户端获取动态组合的配置文件。核心目标是创建一个可分享的订阅链接，让朋友或团队成员也能使用组合好的配置。

## 需求总结

### 核心功能
1. **选择多个订阅** - 合并所有订阅节点
2. **设置代理组** - 支持同时设置多个代理组，每个组可以选择：
   - 标签匹配（包含关键词）
   - 直接选择节点
   - 选择全部节点
3. **设置规则** - 选择多个规则组，支持按规则组排序，排靠前的规则组优先级高
4. **设置基础信息** - 管理端口、代理端口、认证账号、管理密钥等配置

### 认证与访问
- **身份认证** - Basic Auth 认证方式
- **URL 格式** - 基于名称的 URL 路径，如 `/api/config/{name}`
- **输出格式** - 标准 Clash YAML 配置

### 存储与生命周期
- **永久保存** - 配置创建后永久保存，除非手动删除
- **定时刷新** - 支持 cron 表达式定时刷新订阅源

### 数据来源
- **订阅源** - 复用现有的订阅源管理
- **规则组** - 复用现有的 `data/rule-groups/` 目录数据
- **基础信息** - 每个配置独立存储基础信息

## 实现方案

### 选定方案：基于现有模块扩展

**核心组件**：
- **ConfigProfile 模型** - 存储配置组合
- **ConfigGeneratorService** - 负责生成 Clash 配置
- **ConfigController** - 提供 REST API，支持 Basic Auth
- **ScheduledRefreshTask** - 定时刷新订阅源

**优点**：
- 复用现有代码，开发量小
- 与现有系统集成紧密
- 维护成本低

## 设计决策

1. **代理组匹配方式** - 使用包含关键词的方式匹配节点
2. **规则组管理** - 基于现有的 rule-groups 目录数据
3. **基础信息存储** - 每个配置独立存储
4. **URL 路径** - 基于名称，需要处理名称冲突
5. **认证方式** - Basic Auth
6. **定时任务** - 支持 cron 表达式定时刷新订阅源
